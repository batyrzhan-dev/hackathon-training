# Городской помощник — рабочее название

> Планируемый AI-помощник для обработки обращений жителей. Сейчас подготовлены только проектные документы; приложение не реализовано и не развёрнуто.

## Problem

Оператор вручную читает жалобы, определяет категорию, ищет повторы и выбирает приоритет.

## Target users

Сотрудники городской службы, выполняющие первичную обработку обращений.

## Solution

Планируется преобразование текста в карточку с категорией, кратким описанием, похожими обращениями и объяснимой рекомендацией приоритета. Решение проверяет оператор.

## Value

Ожидается сокращение ручного чтения и поиска. Измерений эффективности пока нет.

## Main scenario

Текст о неисправном фонаре и искрении → AI-анализ → поиск старой жалобы → правило P1 с цитатой → подтверждение сотрудником. Целевое время демо — 30–60 секунд, ещё не проверено.

## Key features

Запланированы, пока не реализованы:

- Ввод текста, категория и краткое описание.
- Поиск похожих обращений и кандидатов в дубли.
- Приоритет по явным правилам с основаниями.
- Карточка с подтверждением/исправлением сотрудником и сохранением решения.

## AI role

План: понимание текста, извлечение признаков с цитатами, summary, embeddings для смыслового поиска. Валидация, приоритет, пороги и хранение — обычный код. Автоматического объединения обращений не предполагается.

## Architecture

Планируемый поток: UI → backend → AI → проверка структуры → поиск по истории → правила → карточка → решение оператора → сохранение. Подробная схема находится в CASE.md.
